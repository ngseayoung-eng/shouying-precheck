# 规则定制指南：把贵司制度变成技能的规则文件

技能自带的是**公开法规版**规则（GSP、《药品网络销售监督管理办法》、网售禁售清单、官方查询入口）。每家企业的首营制度都有自己的口径——收什么、豁免什么、卡多严。这份指南讲怎么把贵司制度蒸馏成规则文件，替换技能附录，让预审按**你的口径**执行。

## 为什么规则是"文件"而不是"写死在提示词里"

规则和工程纪律是分层的：

- **工程纪律**（交互门、盲区≠缺失、多源校验、自检门）——通用，不用改
- **规则内容**（该收哪些资料、每项的硬要求、豁免清单）——每家公司不同，**做成数据文件整体替换**

好处：制度修订时只换规则文件、不动技能；规则版本独立管理；质管审规则改得动提示词的命。

## 规则文件的结构（保持不变）

附录分五节，规则 ID 稳定不变——改内容不改 ID，方便比对版本：

| 节 | 内容 | ID 前缀 |
|---|---|---|
| §0 | 禁售校验（品种第一道闸） | BAN |
| §1 | 首营企业资料 | G（通用）/ C（品类专属） |
| §2 | 首营品种资料 | VG（通用）/ V-（品类专属） |
| §3 | 全局核验链 | CHK |
| §4 | 程序与执行细则 + 豁免清单 | PROC / E |

每条规则三要素：**资料名 / 硬要求 / 常见错法**。"常见错法"列实测很有用——它教 AI 往哪看。

## 蒸馏流程（从制度文档到规则文件）

1. **取源**：找到贵司现行有效的首营管理制度文本（质量管理制度汇编里的首营企业/首营品种审核章节）。别凭经验写——制度是唯一的规则源头。
2. **逐节转写**：制度里每一项资料要求 → 一条规则（沿用对应 ID）。制度的执行口径（比如"检验报告任一即可""商标证不强制"）写进"硬要求"列，并注明"执行口径"。
3. **补豁免**：贵司对 AI 预审的例外口径（哪些项预审不管控）写进 §4.1 豁免清单。
4. **实测校准**（最关键、最容易被跳过）：拿 3–5 个真实首营资料包跑预审，把 AI 的每个误报/漏报追到规则层——是规则缺失、规则过严、还是表述歧义，改规则再跑。规则文件的可信度 = 校准轮数。
5. **定版本**：试点期用 0.x 版本号，质管校对通过后升 1.0。每次修订写一行修订记录（改了哪条、为什么）。

## 三个实操提醒

- **跨文件核对判断不进对外补料清单**：规格不一致、码对不上、权属存疑这类判断，写进规则时保持"内部确认"路由——它们是提给质管的线索，不是对供应商的要求。这条对外件的公信力命脉，定制时别改掉。
- **经营范围写活**：CHK-3 用的本公司经营范围，写"以最新证照为准，由使用人提供"，别把证载明细固化进规则（会过期）。
- **法规条文核对原文**：涉及具体条文号的，以官方发布原文为准再写进规则，别转抄二手材料。
